# 打卡策略双模式落地方案

日期：2026-07-28

## 1. 目标

模块新增不可变记录策略 `recordPolicy`：

- `strict`：严厉模式，保持现有规则；
- `relaxed`：轻松模式，用于纯记录，不走补卡审批；
- 现有模块及旧本地数据全部迁移为 `strict`；
- `recordPolicy` 与现有 `mode: solo | group` 完全独立；
- 创建模块时必须明确选择策略，创建后不能修改；
- 同一成员在同一模块、同一日期最多保留一条有效记录。

## 2. 产品规则

| 策略 | 日期范围 | 生效规则 | 编辑和删除 |
|---|---|---|---|
| strict | 今天 | 媒体处理完成后直接生效 | 仅本人当天可操作 |
| strict + solo | 过去 3 天 | 直接生效并锁定 | 不可操作 |
| strict + group | 过去 3 天 | 其他活跃成员审批后锁定 | 不可操作 |
| relaxed | 1900-01-01 至 2099-12-31 | 媒体处理完成后直接生效，不创建业务审批 | 本人任意日期均可操作 |

补充规则：

- 日期必须是真实存在的公历日期，所有业务日期以 `Asia/Shanghai` 为准；
- 轻松模式记录统一使用 `source=normal`，不得伪装为补卡记录；
- 记录日期本身不可编辑，改日期通过删除后在目标日期重新创建；
- 其他成员的记录永远不可编辑或删除；
- 媒体审核和贴纸处理仍然适用于轻松模式，“直接生效”表示无需补卡审批；
- 未来记录立即出现在日历和图库，但到达该日期后才进入连续天数、周统计和共同完成统计；
- 首页预览仍只展示今天的有效记录。

## 3. 数据模型与不可变性

在 `life_module` 新增：

```sql
record_policy VARCHAR(16) NOT NULL DEFAULT 'strict'
```

迁移使用新的增量 SQL 文件，不修改已执行迁移。默认值保证历史模块自动成为严厉模式。

不可变性由三层保证：

1. 创建接口要求显式传入 `strict` 或 `relaxed`；
2. 模块更新接口不提供该字段，并对携带该字段的请求返回 `RECORD_POLICY_IMMUTABLE`；
3. 数据库不变量检查确认字段值始终属于允许集合。

本地 Mock 数据库提升 schema 版本，为所有旧模块补 `recordPolicy: strict`。

## 4. 服务端策略

抽取统一日期策略服务，所有写接口复用同一判断：

- strict 普通记录：只能写今天；
- strict 补卡：只能写 D-1 至 D-3；
- relaxed 普通记录：允许技术边界内任意日期；
- relaxed 补卡接口：拒绝调用，不创建审批、通知和待办；
- 编辑删除：strict 仅今天，relaxed 为边界内任意日期；
- 记录所有权、模块成员资格、模块状态及乐观锁继续由服务端校验。

策略判断覆盖普通媒体上传初始化、普通记录保存、补卡申请、编辑、删除和接口动作聚合，不能只依赖前端隐藏按钮。

## 5. 统计投影

每日快照计算抽成可复用服务，由定时任务和记录写入链路共同调用：

- 历史快照已存在时，保留原有成员集合，只重新计算完成状态；
- 历史快照不存在时，按目标日期 23:59:59 的成员关系创建；
- 保持现有口径：快照中至少一名成员且全部完成即记为完成，避免严格模式统计回归；
- 过去记录新增、删除、严厉模式单人补卡生效、多人补卡审批通过后立即重算目标日；
- 未来记录不提前创建每日快照，由该日期结束后的定时任务生成。

月度卡片采用“写入时失效、读取时重建”：

- 有效记录新增、编辑、删除或审批生效后，使对应月份卡片数据版本失效并清理旧导出引用；
- 读取卡片时按当前有效记录和快照重新生成卡片项；
- 周/月完成类统计不提前计算未来日期；
- 历史补录后，月度记录数、共同完成天数和卡片素材在下一次读取时立即正确。

详情页通过独立的模块月统计接口读取服务端权威值，避免历史补录完成后仍命中客户端旧缓存。

## 6. 前端交互

创建模块面板增加无默认值的策略二选一：

- 严厉模式：今天正常记录；过去 3 天可补卡；多人时需其他成员审批；历史记录生效后不可修改；
- 轻松模式：可记录 1900 至 2099 年任意日期；无需补卡审批；本人记录以后仍可编辑或删除；
- 固定提示“创建后不能更改”；未选择策略不能提交。

详情页按策略生成日期动作。编辑器模式不能再根据“是不是今天”判断是否补卡，而应由明确动作决定。轻松模式提供日期选择器和跨月导航，历史、今天、未来均可新增或编辑。

模块设置页只读展示当前策略，不提供修改入口。

## 7. 测试与验收

- 历史服务端模块和本地旧数据全部迁移为 strict；
- 创建缺少或传入非法策略失败，创建后读取接口返回一致策略；
- 任意模块更新请求都不能修改策略；
- strict 今天普通记录成功，过去或未来普通记录失败；
- strict D-3 补卡成功、D-4 失败，solo/group 原有行为不回归；
- relaxed 在两个技术边界以及任意过去、今天、未来日期均可记录；
- relaxed 不产生补卡审批、通知或待办；
- relaxed 历史和未来本人记录可编辑删除，其他成员不可操作；
- 同成员同日并发创建仍只有一条有效记录；
- 历史新增和删除会重算每日快照，但不覆盖历史成员集合；
- 未来记录不提前进入完成类统计；
- 月度卡片在历史补录后失效并重建；
- 本地 Mock、远程 API、生产构建、迁移清单和 OpenAPI 校验全部通过。

## 8. 发布顺序

1. 发布数据库增量迁移，字段默认 strict；
2. 发布服务端策略读取、写入校验和统计重算；
3. 发布带强制选择控件的小程序版本；
4. 执行迁移清单、数据库不变量和集成冒烟检查；
5. 观察创建失败率、日期拒绝错误、补卡审批量和统计重算错误。

本次采用服务端与小程序同批发布，创建参数直接强校验为必填；发布数据库迁移后再切换服务端和小程序版本。
