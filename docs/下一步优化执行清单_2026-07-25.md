### T3　修复 COS 触发云函数高危依赖

**目标**：`npm audit --omit=dev` 归零，且 COS 事件转发功能回归通过。

**为什么**：4 高危 1 中危（`lodash` 原型污染），是平台审计与安全风险。好消息是 `index.js` **只用 `init()` + `callContainer()`**，漏洞来自未被使用的 `@cloudbase/database`。

**详细 TodoList**（按优先方案，逐级降级）：
- [ ] 方案 A（首选）：在独立分支升级 `@cloudbase/node-sdk` 到 CloudBase 官方当前推荐版本，`rm -rf node_modules package-lock.json && npm install`
- [ ] 重新 `npm audit --omit=dev`，确认高危归零；若新版仍带 `@cloudbase/database`，评估 `npm dedupe` 或 `overrides` 锁 `lodash.set/unset` 到修复版
- [ ] 方案 B（备选，若 A 不达标）：用 `overrides` 强制 `lodash.set`/`lodash.unset` 到已修复版本，重装并复审计
- [ ] 方案 C（兜底）：改为不依赖完整 SDK 的调用方式（云函数内以受支持的容器调用替代），仅保留 `callContainer` 能力
- [ ] 回归三点：① COS 事件 JSON 解析 ② `x-storage-event-token` 校验 ③ `callContainer` 到 `/internal/storage/object-created` 返回 <300
- [ ] 用一张真实 `original.jpg` 走通"上传→触发→后端 processing"，确认 `objectKey` 无嵌套路径
- [ ] 若临时无法升级：在 `docs/风险登记` 写明风险接受人、限制入口、完成期限
- [ ] 更新云函数 `package-lock.json` 并纳入 Git

**交付物**：干净审计的云函数 + 回归记录。
**验收标准**：`npm audit --omit=dev` 显示 `0 high, 0 critical`；一次真实 COS 事件端到端转发成功。
**预计工时**：0.5–1 人日。
