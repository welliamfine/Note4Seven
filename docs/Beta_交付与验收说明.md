# Beta 交付与验收说明

## 交付范围

本次 Beta 在 Alpha 核心记录闭环之上完成多人关系功能，沿用微信原生小程序、TypeScript、本地服务适配器和现有毛玻璃视觉体系。在线 Figma 文件当前账号无读取权限，因此新增页面依据工作区内的原型文件、PRD V6.4、页面流程、状态机和 UI 规范实现。

已实现：

- 邀请生成、24 小时有效期、分享预览、公开邀请介绍和申请加入；
- 4 人上限、重复申请、拒绝后 24 小时冷却、7 天申请过期；
- 通知卡片内同意/拒绝，审批后生成全新成员实例和递增加入顺序；
- 成员管理、创建者转让、移出成员、普通成员退出及审计记录；
- 退出立即失去模块、日历和回应访问权，历史回应匿名保留；
- 全局通知与模块待办分别统计、单条/全部已读；
- 固定六种回应，每人每条记录最多一个，支持更换和取消，禁止回应自己；
- D-1 至 D-3 补卡：单人直接锁定，多人生成待审批记录；
- 补卡首个有效审批决定结果、申请人禁止自审、24 小时过期；
- 模块设置中的基础信息、邀请入口、撤销邀请和成员退出。

## 验收路径

1. 在“我的 → 通知中心”查看演示加入申请，执行同意或拒绝。
2. 从首页进入任意模块，点击成员区域进入成员管理；创建者可邀请、转让或移出成员。
3. 在成员管理页点击邀请卡，验证倒计时和微信分享路径。
4. 在日历详情点击他人的日期记录，验证回应的新增、更换和再次点击取消。
5. 点击 D-1 至 D-3 的空日期提交补卡；多人模块在“待办”中由其他成员审批。
6. 普通成员从模块设置退出后，首页不再显示该模块，直接访问详情返回权限错误。

## 自动检查

运行：

```powershell
npm run verify
```

自动检查覆盖 TypeScript、19 条日期/动效/业务契约测试、11 个页面构建产物、JSON 和静态资源引用。业务契约包含邀请审批、成员实例、重复审批、回应互斥、单人/多人补卡、补卡幂等和退出即失权。

## 环境边界

当前工作区没有正式 AppID、云数据库、对象存储、抠图服务和订阅消息配置，因此以下能力保留正式接口边界但未伪装为生产完成：

- 邀请卡中的小程序码为视觉占位，微信分享路径可用；
- 并发审批由本地同步状态检查验证，生产环境仍需数据库事务和行锁；
- 通知为小程序内通知，不包含微信订阅消息；
- 媒体处理继续由本地透明贴纸素材模拟。

接入生产后端时，页面层继续调用 `src/services/api.ts` 的现有契约，替换服务适配器即可。
