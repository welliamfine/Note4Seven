# 记录我的一辈子｜埋点文档 V1.1（Figma统一对齐版）

> 依据：PRD V6.4、页面流程 V6.4、接口文档 V1.1、状态机 V1.1。  
> 目标：覆盖核心漏斗、Figma已展示页面、PRD补充流程、性能质量和异常监控。  
> 原则：不采集原图、图片URL、备注全文、明文邀请Token或OpenID。

---

## 1. 事件规范

### 1.1 命名

```text
<domain>_<object>_<action>
```

示例：

```text
home_module_click
record_media_process_success
join_application_approve
```

事件名使用小写snake_case。事件发生时间由SDK记录，关键成功事件同时以服务端业务事件校准。

### 1.2 通用字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `eventId` | string | 是 | 客户端事件唯一ID |
| `userId` | string | 登录后 | 用户ID |
| `sessionId` | string | 是 | 小程序会话 |
| `anonymousId` | string | 是 | 登录前设备匿名标识 |
| `pageName` | string | 是 | 标准页面名 |
| `pageInstanceId` | string | 是 | 页面实例 |
| `entrySource` | string | 是 | 来源入口 |
| `moduleId` | string | 否 | 模块ID |
| `memberInstanceId` | string | 否 | 当前成员实例 |
| `moduleMode` | string | 否 | solo/group |
| `memberCount` | int | 否 | 活跃成员数 |
| `recordDate` | string | 否 | 业务日期 |
| `networkType` | string | 是 | wifi/4g/5g/unknown |
| `appVersion` | string | 是 | 小程序版本 |
| `documentBaseline` | string | 是 | `prd_6.4` |
| `timestamp` | int64 | 是 | 客户端毫秒时间 |
| `serverTimeOffsetMs` | int64 | 否 | 与服务端时间偏移 |
| `result` | string | 否 | success/fail/cancel |
| `failReason` | string | 否 | 标准失败码 |
| `durationMs` | int | 否 | 操作耗时 |

### 1.3 禁止采集

- 原始照片、base64、图片URL、对象存储Key；
- 透明贴纸内容或主体识别结果；
- `remark`全文；
- 用户真实聊天或联系人；
- 明文邀请Token、小程序码内容；
- OpenID、UnionID原文；
- IP原文；
- 用户昵称和头像URL。

可采集：

- `hasRemark`；
- `remarkLengthBucket`；
- `fileSizeBucket`；
- `imageSourceType`；
- 标准化失败码。

# 23. 核心指标口径

| 指标 | 口径 |
|---|---|
| 首次创建模块率 | 新用户7日内至少一次module_create_success / 新登录用户 |
| 首次打卡完成率 | 新用户7日内至少一次record_submit_success / 新登录用户 |
| 图片上传成功率 | media_upload_success / media_upload_start |
| 抠图成功率 | media_cutout_success / media_cutout_start |
| 打卡完成率 | record_submit_success / record_editor_view去重会话 |
| 邀请打开率 | invite_landing_view去重用户 / invite_share_click |
| 加入申请率 | join_application_success / invite_landing_view有效用户 |
| 加入通过率 | join_application_approve_success / join_application_success |
| 7日记录留存 | 首次记录后第7自然日有正式记录的用户 / 首次记录用户 |
| 共同完成率 | completed快照天数 / 可计算多人模块天数 |
| 回忆卡保存率 | memory_save_success / memory_card_view |
| 日期详情转记录率 | record_editor_view来源date_detail / date_detail_sheet_view可记录场景 |

# 24. 埋点验收

- [ ] Figma每个已展示一级页、二级页和底部面板均有view事件；
- [ ] 未来日期面板有view但没有记录按钮点击事件；
- [ ] 照片来源面板区分拍照和相册；
- [ ] 新增与编辑共用record_editor事件并通过editorMode区分；
- [ ] 首页贴纸进入、替换、删除动画分别上报；
- [ ] 双人日历上报layoutType=two_vertical；
- [ ] 不存在模块头像、快速打卡或无照片提交埋点；
- [ ] 不采集remark全文和图片URL；
- [ ] 加入审批卡片支持processing、success、conflict；
- [ ] 服务端成功事件与客户端点击事件可通过clientRequestId关联。
